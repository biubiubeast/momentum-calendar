# 交易计划设计提案（只设计，不开发）

状态：2.1 设计讨论稿。没有增加交易表单、自动行情、券商连接或下单能力。

## 建议：交易计划是独立业务记录，可归属长期任务

不要把一笔交易直接等同于日历事件，也不要要求每一笔交易新建“产品”。建议在未来增加独立的“交易计划”记录：它有假设、执行条件、失效条件、版本和生命周期。它可以属于某个长期任务，例如“期权策略研究与验证”；日历继续记录“研究 90 分钟”“盘后复盘 30 分钟”等投入；事件保留财报、到期日、经济数据发布时间等时点。

| 概念 | 回答的问题 | 例子 | 与其他记录关系 |
| --- | --- | --- | --- |
| 产品 / 长期任务 | 长期想交付或验证什么？ | 建立策略手册、完成模拟验证 | 一个任务可以包含多个交易计划 |
| 交易计划 | 满足什么条件才行动，何时认错？ | 某标的某策略的预案 | 可关联一个长期任务，有独立版本 |
| 日程时间块 | 什么时候做研究和管理，花了多久？ | 周一 09:00–10:30 研究 | 关联计划，可沿父任务汇总一次 |
| 事件 / 提醒 | 什么时间节点需要关注？ | 到期日、财报日、计划复查 | 一个计划可以关联多个事件 |
| 执行记录 | 实际发生了什么？ | 模拟成交、分批开仓、平仓 | 一份计划对应多条实际记录 |
| 交易复盘 | 决策、执行、结果分别如何？ | 偏离原因、改进动作 | 链接计划版本和执行记录 |

以此关系保留一个日程唯一计时归属。若时间块关联交易计划，父长期任务通过计划继承，不把同一段时长重复加在两处。交易记录中的持仓时长也不属于人的专注时长。

## 一页工作流

“草稿 → 待执行 → 执行中 → 已结束 → 已复盘”；另有“取消 / 失效”。“没有交易”也可以是遵守计划的正确执行，不应为了完成率而鼓励开仓。取消与失效需要原因，不默认归为失败。

计划面板展示：当前假设、下一触发条件、失效条件、下次复查时间、关联事件与最新复盘。开始执行前保存一个不可修改的计划版本；之后的修改另存版本并写明原因。实际执行记录引用当时的版本，防止事后改写原计划。

## 首期最小字段

基础：名称、市场/标的、模拟或实盘（默认模拟）、账户别名（不存凭据）、策略类型、方向、交易币种、所属长期任务、标签。

决策：为什么考虑、支持证据/来源及时间、触发条件、停止考虑的条件、计划有效期、复查日期、替代情景和暂不交易条件。条件先用结构化选项加文字，不在首期自动判断价格触发。

风险计划：由用户填写计划资金、数量、预估最大损失及其假设、退出条件、是否已核对流动性和事件风险。不预填“推荐”仓位或风险百分比。条件单/止损价格并不等于保证能以该价格成交；表单应允许记录跳空、滑点和费用假设。

执行：时间、动作、数量、价格、费用、币种、关联计划版本；分开记录计划值和实际值。首期可手工记录，不发送券商指令。

复盘：是否按计划执行、偏离点与原因、当时可用的信息、下一次改进；实际盈亏与决策质量分栏。未成交/主动放弃也可复盘。

## 期权和复杂策略的扩展方式

不要将多腿期权塞进单一“买入价/止损价”。后续增加 legs 数组：标的、到期日、看涨/看跌、行权价、买卖方向、合约数、合约乘数、价格与币种。一份计划可有多次调整，每次调整引用旧腿和新腿，保留版本链。

已实现/未实现盈亏、保证金和收益图只有在合约乘数、币种、费用、行情时间及公司行动规则明确后再开发；尚无可靠数据时显示“未计算”，不要显示 0。组合风险不通过简单相加百分比估计。

## 日历和提醒

研究、盯盘管理、复盘都是时间块；财报、交割/到期、计划复查是事件。首期沿用网页提醒和 ICS 导出，不声称关闭页面还能收到网页提醒。价格触发需要行情源、时效和后台通知服务，是后续独立能力，不能用普通日历闹钟替代。

## 统计怎样避免误导

把三类结果放在并列卡片：研究/复盘投入；计划执行质量；交易财务结果。任务完成率只看约定的工作，不由盈利与否决定。盈利不证明流程正确，亏损也不能单独证明没有遵守计划。

首期优先展示“按计划执行比例（用户评价）”“完成复盘比例”“偏离原因分布”。收益率、胜率、回撤等需先明确分母、现金流、样本量和未平仓处理，再支持统计；少量样本不显示夸大的判断性评级。

## 页面建议

交易计划列表：状态、市场/标的、模拟/实盘、标签、所属任务、下次复查筛选。详情从“决策摘要”开始，之后是执行时间线和复盘，财务结果独立区域。长期任务页展示关联计划数量和工作投入，日历选择计划后自动显示其父任务。

建议后续拆成三小版：①手工计划与复盘；②分批执行、多腿和严格核算；③经授权的行情/通知。券商接入、自动下单另立安全与授权设计，不顺带加入。

## 开工前需要决定

主要记录研究还是实盘；常用市场与资产类型；是否第一期就必须支持多腿；是否需要团队共享；交易数据保留期限。先用默认“个人、手工、模拟”的可用原型验证流程，再确定长期数据模型。
