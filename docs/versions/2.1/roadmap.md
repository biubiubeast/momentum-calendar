# 后续升级建议

## 优先级 P0：长期可靠性

1. 将整个 journal 的覆盖式保存逐步拆成项目、日程、复盘表，增加按记录修订号和操作审计。当前 1.5 MB 是长期记录的容量瓶颈；先做容量提示、可验证备份，再设计分页与归档。验收：大数据量不卡顿、并发编辑只冲突于同一记录。
2. 复盘草稿自动保存与离开提示；失败时保留本地草稿并明确显示未同步，避免把“已输入”当成“已保存”。
3. 版本回退兼容：旧版本无法认识 2.1 数据，需要保留新字段或只读降级。发布前验证数据恢复演练，禁止通过恢复旧数据库来直接回退新记录。

## 优先级 P1：更好的成果管理

1. 可调整里程碑顺序、目标日期和验收条件，将“完成”的定义明确化；增加成果链接和附件，先定义存储配额与访问权限。
2. 卡点增加下一步、责任人和复查日期；支持依赖关系与阻塞天数，避免仅靠重要度排序。
3. 标签同义词/大小写合并、AND/OR 切换、保存筛选视图；大类重命名与归档不改变历史身份。
4. 增加真实活动日志，以“发生日期”和“记录时间”分别排序，避免补记掩盖历史。
5. 项目详情长列表分页；性能基准覆盖 2 万日程、1 千项目。减少逐项目重复扫描。

## 优先级 P2：复盘与激励

1. 周复盘自动带入成果、未解决卡点、计划/实际偏差，并由用户确认总结，不编造缺失进展。
2. 增加可选自定义复盘提示和主观状态评分，支持按月观察趋势；不把全天忙碌等同于高价值。
3. Excel 增加图表、可冻结的周期快照和跨期比较；快照需记录时区、计算版本、生成时间与数据修订号。
4. 若需要共享，先实现成员身份、每项目访问权限和审计，再开放协作；当前合作人字段不能作为授权依据。

## 下一版候选

交易计划先做“计划—手工执行记录—复盘”，详见交易计划提案。自动行情、券商接入、自动下单和投资建议均不属于首期。建议先用 2–3 周真实记录检验字段负担，再决定增加自动化。
